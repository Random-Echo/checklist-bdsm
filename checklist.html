Aide

Comprendre la checklist

Le catalogue contient 685 pratiques réparties dans 30 catégories, plus vos pratiques personnalisées. L’application sert à préparer une comparaison de couple sans exposer les réponses trop tôt : on répond d’abord séparément en Édition, puis on croise les résultats en Lecture.

1. Édition : répondre séparément

Choisissez la personne qui répond. La couleur de l’interface indique la personne active. Seules ses réponses, ses notes et ses états Avant sont affichés ; les choix de l’autre personne restent cachés.

Les pratiques générales utilisent INTÉRÊT. Les pratiques dirigées utilisent DOM et SUB pour garder un vocabulaire stable, même si la direction réelle de l’action varie selon la configuration.

2. Lecture : comparer le couple

Le mode Lecture croise les réponses compatibles, affiche le résultat du couple et laisse les réponses personnelles verrouillées. La couleur indique le dominant actuellement sélectionné ; changer le dominant change la lecture des variantes concernées.

Les actions communes restent disponibles : Fait ensemble, épingles, filtres, tirage aléatoire et séance.

3. Préférences

? = non renseigné · 🚫 = limite · ⏳ = pas maintenant · 💭 = fantasme · 😐 = neutre · 🔥 = envie · 👑 = favori.

Avant signifie seulement que la personne a déjà expérimenté la pratique. Fait ensemble signifie que le couple l’a déjà pratiquée ensemble. Ces deux informations sont indépendantes de la préférence actuelle.

4. Notes

Chaque réponse peut avoir une note personnelle. En Édition, seule la note de la personne active est visible. En Lecture, les notes utiles à la comparaison sont affichées avec le nom et le rôle correspondant.

5. Profils et logique D/s

Les pseudos, couleurs, attributs anatomiques et la dynamique D/s sont définis dans les profils. Les attributs sont indépendants du genre : l’application s’en sert uniquement pour masquer les pratiques incompatibles avec la configuration actuelle.

En dynamique fixe, seuls les rôles configurés sont proposés. En switch, les deux directions peuvent être renseignées et comparées.

6. Catalogue personnalisé

Les pratiques ajoutées sont rangées dans Personnalisé. Leur nom et leur description sont communs au français et à l’anglais. Les variables {A}, {B}, {DOM} et {SUB} insèrent automatiquement les bons pseudos selon la variante affichée.

Vous pouvez aussi définir le niveau de risque et, si nécessaire, les conditions anatomiques côté DOM et côté SUB.

7. Filtres, tirage et séance

Recherche, catégories et filtres fonctionnent dans les deux modes. Le tirage aléatoire et le Mode séance utilisent uniquement les variantes disponibles pour la configuration du couple et les filtres actifs.

Une 🚫 limite peut être marquée Fait ensemble si elle a réellement été vécue, mais elle n’est pas proposée pour une nouvelle séance.

8. Partage et sauvegardes

🔗 Partager la configuration contient uniquement les pseudos, couleurs, attributs anatomiques et la dynamique D/s. Il ne contient ni réponses, ni notes, ni pratiques personnalisées.

💾 Complète sauvegarde tout le couple. Une sauvegarde Personne A/B ne contient que les données personnelles de cette personne : profil, anatomie, couleur, réponses, notes, états Avant et pratiques personnalisées utilisées.

À l’import, vous choisissez l’emplacement à remplacer. Les données communes de l’ancien couple, comme Fait ensemble, la séance et les réglages de sécurité, ne suivent pas dans une sauvegarde individuelle.

9. Données locales

Les profils, réponses, notes, pratiques personnalisées, états, réglages de sécurité, séance et préférences d’affichage sont enregistrés localement dans ce navigateur. Un autre appareil ne reçoit rien automatiquement : utilisez le partage de configuration ou les sauvegardes JSON selon le besoin.

The catalogue contains 685 practices across 30 categories, plus your custom practices. The app is designed to prepare a couple comparison without revealing answers too early: answer separately in Edit, then compare results in Reading.

1. Edit: answer separately

Choose the person who is answering. The interface colour shows the active person. Only their answers, notes and Before states are displayed; the other person's choices stay hidden.

General practices use INTEREST. Directed practices use DOM and SUB so the wording stays stable, even when the actual direction changes with the configuration.

2. Reading: compare the couple

Reading mode matches compatible answers, shows the couple result and locks personal answers. The colour shows the currently selected dominant; changing the dominant changes how the relevant variants are read.

Shared actions remain available: Done together, pins, filters, random draw and session.

3. Preferences

? = unrated · 🚫 = limit · ⏳ = not now · 💭 = fantasy · 😐 = neutral · 🔥 = want to · 👑 = favorite.

Before only means that the person has already experienced the practice. Done together means the couple has already practiced it together. Both are independent from the current preference.

4. Notes

Each answer can have a personal note. In Edit, only the active person's note is visible. In Reading, notes useful to the comparison are shown with the matching name and role.

5. Profiles and D/s logic

Names, colours, anatomy attributes and D/s dynamic are defined in profiles. Anatomy attributes are independent from gender: the app only uses them to hide practices that do not fit the current configuration.

With a fixed dynamic, only configured roles are offered. In switch mode, both directions can be answered and compared.

6. Custom catalogue

Added practices are stored under Custom. Their name and description are shared by French and English. Variables {A}, {B}, {DOM} and {SUB} automatically insert the right names for the displayed variant.

You can also set the risk level and, when needed, anatomy requirements for the DOM and SUB sides.

7. Filters, random draw and session

Search, categories and filters work in both modes. Random draw and Session mode only use variants available for the couple configuration and the active filters.

A 🚫 limit can be marked Done together if it was actually experienced, but it is not offered for a new session.

8. Sharing and backups

🔗 Share configuration contains only names, colours, anatomy attributes and the D/s dynamic. It contains no answers, notes or custom practices.

💾 Full backs up the whole couple. A Person A/B backup contains only that person's personal data: profile, anatomy, colour, answers, notes, Before states and custom practices they use.

On import, you choose which slot to replace. Shared data from the previous couple, such as Done together, session and safety settings, does not travel in an individual backup.

9. Local data

Profiles, answers, notes, custom practices, states, safety settings, session and display preferences are stored locally in this browser. Another device receives nothing automatically: use configuration sharing or JSON backups depending on what you need.
